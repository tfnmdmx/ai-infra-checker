comb_camera-ppa-001 — 相机检查程序是否完整运行#

所属模态算子：Comb Camera

active error 时产物可生成 multi · check processing_artifact_anomaly raw_to_processed rule v1.0.0 fm-comb-camera-operator v0.3.0

记录 MCAP 二次扫描、ffmpeg/ffprobe 环境检查或视频解码任务自身崩溃等运行问题，避免把“没有执行完”误报为数据通过。

白话解释#

  • 做了什么检测： 监控检查程序本身是否正常工作，例如视频工具是否安装、第二次读取时文件有没有变化、解码子任务有没有超时或崩溃。

  • 为什么会告警或不通过： 这里失败通常表示运行环境或执行流程出了问题，不等同于视频内容质量差；受影响的规则没有可靠跑完，必须修复后重试。

计算契约#

计算契约（不可直接调用）

    processing_run: MCAP and runtime process state,
    *,
    decode_timeout_s: float = 600.0,
) -> RuleResult

implementation · registry · test 1 · 计算规范

注意

  • 本规则是“程序执行异常”，不是“数据质量指标”；MCAP 本身无法完整读取由 comb_camera-idc-001 表达，正常执行后发现坏视频由 comb_camera-dsf-001 表达。

  • 外层 value/unit/threshold 为 null；每个 check 实例的 details 提供 exception_type 和 reason。

  • 是否仍有产物取决于失败阶段：视频运行依赖或解码执行失败时没有新配对索引；更晚阶段已有产物时以 processed_ok 和 artifacts 为准。

执行异常处理#

事件含义#

发布 error 表示： mcap_scan、video_runtime 或 video_decode 任一执行点抛出未被输入/数据规则覆盖的异常

具体捕获点#

  1. mcap_scan：捕获临时目录创建、第二遍 MCAP 扫描/提取异常，以及两遍扫描之间文件变得不可读、消息计数或身份冲突结果发生变化。

  2. video_runtime：解析 ffmpeg 和 ffprobe 可执行文件；工具缺失或不可运行时发布执行异常，并跳过解码与八路配对。

  3. video_decode：捕获解码任务未按预期返回结果的异常；正常返回但发现坏消息属于 comb_camera-dsf-001，不在本规则重复计数。

  4. 每个失败点按 target_type=check、target_id=mcap_scan|video_runtime|video_decode 发布实例，保留异常类型和原始原因。

执行关系#

前置质检算子： 无。

产物影响： 本规则为 error 时，只记录质量异常，不阻止生成结构上有效的产物。 如果后续处理或写入本身失败，仍可能没有产物；最终事实以 processed_ok 与 artifacts 为准。

失败后建议#

  1. target_id=video_runtime 时确认兼容包或 PATH 同时提供可运行的 ffmpeg 和 ffprobe，并检查执行权限。

  2. target_id=video_decode 时结合 exception_type、reason 和配置的超时检查进程资源、临时磁盘以及工具版本。

  3. target_id=mcap_scan 时确认源文件在算子运行期间没有被继续写入或替换，并检查 scratch_dir 的空间与权限。

  4. 修复后重新运行，确认 summary.skipped_rules 中受影响的 DSF/TSA 规则恢复发布。
