<p class="quality-lead">检查 IMU 数据的「IMU 产物写入异常」，并按公开边界发布独立 RuleResult。</p>

## 白话解释

- **做了什么检测：** 检查处理好的加速度、角速度、磁场和时间数据能否完整保存到输出文件。
- **为什么会告警或不通过：** 创建目录、整理文件内容或写盘失败，意味着没有可靠产物可交给后续环节。

## 执行异常处理
### 事件含义

**发布 error 表示：** 异常时 error

### 具体捕获点

1. 创建目标目录并将 accel、gyro、mag 与 timestamps 写入 processed NPZ。
2. 捕获目录创建、序列化或文件写入抛出的异常，并记录异常类型和原因。
3. 只有文件完整写入后才登记 artifact；任何写入失败都发布 error。

### 判定边界

| 状态 | 条件 |
| --- | --- |
| pass | 未发生该执行事件时通常不发布；事实型执行规则按成功结果发布 pass |
| warn | not_applicable |
| error | 异常时 error |

- 事件型规则没有数值等号边界。

## 执行关系

**前置质检算子：** 无。


**产物影响：** 本规则为 `error` 时，输出契约已经无法满足，因此本次不会登记产物；
原因由结构化 RuleResult 记录。只要这不是运行配置错误，进程仍返回 0。

## 失败后建议

1. 根据 exception_type 和 reason 修复运行环境、转换或文件系统问题。
2. 修复后重试；执行异常不应被静默跳过。
