<p class="quality-lead">检查IMU 数据的「输入读取或未预期处理异常」，并按公开边界发布独立 RuleResult。</p>

## 白话解释

- **做了什么检测：** 观察文件读取、字段整理、时间恢复和输出数据组装过程中有没有意外中断。
- **为什么会告警或不通过：** 处理过程中发生了其他具体规则没有覆盖的程序异常，因此不能确认本次 IMU 数据已经可靠处理完成。

## 执行异常处理
### 事件含义

**发布 error 表示：** 未被输入契约规则覆盖的异常为 error

### 具体捕获点

1. 打开输入 NPZ，并依次完成字段读取、时间轴恢复和输出载荷构造。
2. 捕获未被 IDC、DSF、NVA 或 TSA 规则明确表达的读取与处理异常。
3. 记录失败阶段、异常类型和消息，使执行失败不会被误判为数据质量问题。

### 判定边界

| 状态 | 条件 |
| --- | --- |
| pass | 未发生该执行事件时通常不发布；事实型执行规则按成功结果发布 pass |
| warn | not_applicable |
| error | 未被输入契约规则覆盖的异常为 error |

- 事件型规则没有数值等号边界。

## 执行关系

**前置质检算子：** 无。


**产物影响：** 本规则为 `error` 时，输出契约已经无法满足，因此本次不会登记产物；
原因由结构化 RuleResult 记录。只要这不是运行配置错误，进程仍返回 0。

## 失败后建议

1. 根据 exception_type 和 reason 修复运行环境、转换或文件系统问题。
2. 修复后重试；执行异常不应被静默跳过。
