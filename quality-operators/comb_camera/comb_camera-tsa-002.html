QUALITY OPERATOR · time_sample_alignment

comb_camera-tsa-002 — 八路画面是否全部同步配对成功#

所属模态算子：Comb Camera

active error 时产物可生成 single time_sample_alignment raw rule v2.0.0 fm-comb-camera-operator v0.4.0

以每条 cam0 画面为基准，从其余 7 路选择未使用的最近画面，计算时间跨度合格的完整八目组比例。

先看懂这条规则#

  • 检查什么： 对每张 cam0 画面，在 cam1 到 cam7 各找一张时间最接近且没有被前面分组用过的画面，组成一组后再检查最早与最晚画面的时间差。

  • 什么情况下不通过： 只要有一张 cam0 画面缺少某路近邻、只能复用旧画面，或整组时间差超过允许范围，配对率就低于必须达到的 100%。

判定标准#

状态

怎么判

pass

accepted_groups == denominator_messages，因此 value 必须精确等于 1.0

warn

不会出现；本规则不使用 warn 状态。

error

任一 cam0 消息未能成组，即 value < 1.0

边界怎么算：

  • 30 FPS 的候选组跨度恰好 10 ms 时允许通过；严格大于 10 ms 才拒绝。

implementation · registry · test 1 · test 2 · 计算规范

注意

  • 候选组跨度超限时不会消费任何相机帧；已经接受的组中，8 个源帧索引都永不复用。等距候选选择时间较新的帧。

  • strict_sync 仅表示组跨度不超过 5 ms，便于下游选择更严格子集；正式 pass 上限在 30 FPS 下是闭区间 10 ms。

  • error 时只要 accepted_groups > 0，仍会生成结构安全的部分配对索引；字段包括 timestamps[M]、frame_indices[M,8]、sync_timestamps_ns[M,8]、group_span_ms[M] 和 strict_sync[M]。

计算定义#

计算使用 camera_timelines， 结果类型为 number， 单位为 ratio。

计算方法#

for each cam0 message in original order:
  candidate[c] = nearest not-yet-used frame in camera c, for c = 1..7
  # equal absolute distance selects the newer timestamp
  group_span_ns = max(t_cam0, ..., t_cam7) - min(t_cam0, ..., t_cam7)
  accept only if every candidate exists and group_span_ns <= span_limit_ns
  consume all 8 frame indices only after the group is accepted
value = accepted_groups / total_cam0_messages
span_limit_ns = 10_000_000 at 30 FPS
                else round(1e9 / expected_rate_hz)

  • 聚合口径： 每个 MCAP 发布一个文件级标量；cam0 的原始消息数是固定分母，外层不按相机拆分实例。

  • 无法计算时： 输入、解码或逐路时间任一前置规则失败时不执行；按输入规则约束，正常进入本规则时 cam0 至少有一条消息。

失败后建议#

  1. 先看 failure_counts：no_unused_frame 表示至少一路没有剩余近邻，span_exceeded 表示八路都有候选但组内时间跨度过大。

  2. 用 rejected_cam0_indices 找到失败基准帧，再对比八路 sync_ts_ns，检查固定时钟偏移、帧率不一致、某一路漏帧或乱序。

  3. 若只有 strict_sync_groups 偏少但规则仍 pass，说明所有组满足正式上限、但部分超过更严格的 5 ms 诊断线；不要把 strict_sync 当成本规则失败条件。
