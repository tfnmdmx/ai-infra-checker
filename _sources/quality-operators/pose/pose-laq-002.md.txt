<p class="quality-lead">计算转换前被丢弃的原始 Pose 帧占全部原始帧的比例。</p>

## 先看懂这条规则

- **检查什么：** 把明确标为无效、时间是 NaN/Inf，或姿态值含 NaN/Inf 的原始帧都算作坏帧，再除以原始总帧数。
- **`value` 是什么：** value = 无效原始帧数 / 原始总帧数。无效原因包括显式 invalid、非有限时间戳和非有限姿态值；同一帧命中多项也只计一次。
- **为什么不是 pass：** 坏帧达到 20% 说明有效姿态已经明显缺失；超过 40% 时可用数据不足，因此升级为失败。

### 判定标准

| 状态 | 完整条件 |
| --- | --- |
| **通过 `pass`** | 0 <= value < 0.20。 |
| **告警 `warn`** | 0.20 <= value <= 0.40。 |
| **失败 `error`** | value > 0.40。 |

**边界怎么算：**

- value 恰好为 20% 或 40% 时都是 warn；只有严格超过 40% 才是 error。

## 计算定义
计算使用 `pose_record`，
结果类型为 `number`，
单位为 ratio。

### 计算方法

```text
value = count(~frame_valid) / raw_samples
```

- **聚合口径：** 单条记录发布一个标量。
- **无法计算时：** 前置失败不执行，并记录 skipped_rules。


## 执行关系

**前置质检算子：** 无。


**产物影响：** 本规则为 `error` 时，只记录质量异常，不阻止生成结构上有效的产物。
如果后续处理或写入本身失败，仍可能没有产物；最终事实以 `processed_ok` 与 `artifacts`
为准。

## 失败后建议

1. 查看 details 中的 invalid_flag_samples、nonfinite_timestamp_samples 和 nonfinite_value_samples，先确定坏帧来自哪个环节。
2. 检查上游跟踪状态、时间戳生成和姿态序列化，不要用填零掩盖无效帧。
