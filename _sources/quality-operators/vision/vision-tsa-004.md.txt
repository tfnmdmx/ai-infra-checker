<p class="quality-lead">将相邻源时间戳间隔折算为缺失帧周期，报告最长一次连续缺口。</p>

## 先看懂这条规则

- **检查什么：** 将两帧拍摄时间的间隔换算成缺少了多少个正常帧周期，记录最长一次缺帧的估计时长。
- **`value` 是什么：** 按配置帧周期将每个源时间戳间隔取最近整数（半整数取偶数），减去正常的一个周期，再取最大缺失周期数乘以帧周期；这是局部缺口估计，原始最大间隔另见 details.max_interval_s。
- **为什么不是 pass：** 估计缺帧时长达到 2 个正常帧周期会告警；达到 4 个周期且整段净缺帧比例超过 1% 时会失败。

### 判定标准

| 状态 | 完整条件 |
| --- | --- |
| **通过 `pass`** | value < 2*expected_dt |
| **告警 `warn`** | 2*expected_dt <= value < 4*expected_dt；或 value >= 4*expected_dt 且 missing_ratio <= 0.01 |
| **失败 `error`** | value >= 4*expected_dt 且 missing_ratio > 0.01 |

**边界怎么算：**

- 恰好 2 个缺失周期为 warn；恰好 4 个缺失周期只有净缺帧比例 >1% 才 error。
- missing_ratio 恰好 1% 不满足 error 的净缺失条件。

## 计算定义
计算使用 `video_stream`，
结果类型为 `number`，
单位为 s。

### 计算方法

```text
expected_dt = 1 / expected_fps; value = max(maximum(rint(diff(source_timestamps) / expected_dt) - 1, 0)) * expected_dt
```

- **聚合口径：** 单条规则发布一个标量值；总状态取已执行规则的最高严重度。
- **无法计算时：** 视频输入或源采集时间戳前置失败时不发布本规则；检查在解码前执行，不依赖画面结构或完整解码。


## 执行关系

**前置质检算子：** 无。


**产物影响：** 本规则为 `error` 时，只记录质量异常，不阻止生成结构上有效的产物。
如果后续处理或写入本身失败，仍可能没有产物；最终事实以 `processed_ok` 与 `artifacts`
