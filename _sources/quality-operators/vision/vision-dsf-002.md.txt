# `vision-dsf-002` — 解码帧数是否与消息数一致

[所属模态算子：Vision](../../modality-operators/vision.md)

<p class="quality-lead">核对完整解码帧数与 MCAP 压缩消息数，保证帧索引逐帧对应。</p>

## 先看懂这条规则

- **检查什么：** 把完整解码得到的帧数和容器里记录的视频消息数进行核对。
- **为什么不是 pass：** 两边数量不相等，说明有消息没有成功变成画面或索引对应错位，因此不会生成不可信的帧索引。

### 判定标准

| 状态 | 完整条件 |
| --- | --- |
| **通过 `pass`** | decoded_frame_count == indexed_message_count，且解码帧数可以取得。 |
| **告警 `warn`** | 不会出现；本规则不使用 warn 状态。 |
| **失败 `error`** | 不相等为 error，不生成帧索引产物 |

**边界怎么算：**

- 结构校验按离散条件判定，不进行隐式修复或默认跳过。

### 具体检查项

1. 取得 ffmpeg 完整解码得到的帧数和已建立索引的 MCAP 压缩消息数。
2. 要求 `decoded_frame_count == indexed_message_count`，证明一条压缩消息对应一帧。
3. 解码计数缺失或两者不等时发布 error，并禁止生成帧索引产物。

## 失败后建议

1. 对比 decoded_frame_count 与 indexed_message_count，检查截断码流及一条消息包含多帧的情况。
2. 修复上游帧封装或解码问题；缺少完整解码计数时也不能建立可靠索引。
