# `comb_camera-dsf-001` — 每路视频能否逐帧完整解码

<p class="quality-lead">逐路完整解码 H.264/H.265，确认每条压缩消息只产生一张有效图片，且真实宽高与帧内声明一致。</p>

## 先看懂这条规则

- **检查什么：** 把 cam0 到 cam7 的视频全部解开，逐条确认“一个压缩消息对应一张正常图片”，并核对图片宽高。
- **为什么不是 pass：** 某条消息没有视频数据、编码格式不支持、视频损坏、一次解出零张或多张图片，或声明尺寸与实际尺寸不同，都会标出对应相机和消息位置。

### 判定标准

| 状态 | 完整条件 |
| --- | --- |
| **通过 `pass`** | 8 个 camera 实例的异常消息数 value 都等于 0 |
| **告警 `warn`** | 不会出现；本规则不使用 warn 状态。 |
| **失败 `error`** | 对应相机存在任一载荷、编码、解码、映射或尺寸异常 |

**边界怎么算：**

- bad frame 数量必须等于 0；任意一帧异常即使该相机实例为 error。

### 具体检查项

1. 按相机和连续编码区间把 H.264/H.265 载荷写成临时 Annex-B 分段；空载荷、非 bytes 载荷或其他编码立即标记对应源消息。
2. 对每个分段运行 ffprobe 获取每个解码帧的 `pkt_pos`、width、height，再运行 ffmpeg `-xerror` 完整解码并 flush；诊断、超时或非零退出均不能忽略。
3. 用 `pkt_pos` 将解码帧唯一映射回 `[message_offset, message_offset + payload_bytes)`；每条源消息必须恰好对应一帧，无法定位、一条消息零帧或多帧都记为异常。
4. 解码宽高必须大于 0；frame_meta.width/height 声明为正数时，两者必须与实际解码宽高完全相等。

## 失败后建议

1. 先用 `target_id` 找到失败相机，再用 `bad_indices` 回到该路源消息；`errors` 会区分空载荷、编码、解码、映射或尺寸问题。
2. 解码错误时保留原始 MCAP 和对应 Annex-B 证据，核对编码声明是否在流中途变化、NAL 数据是否完整。
3. 仅尺寸不一致时核对 frame_meta.width/height 的填写端，不要通过忽略尺寸声明把数据判为通过。
