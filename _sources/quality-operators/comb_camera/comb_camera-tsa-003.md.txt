# `comb_camera-tsa-003` — 标定文件是否在采集前 48 小时内生成

[所属模态算子：Comb Camera](../../modality-operators/comb_camera.md)

<p class="quality-lead">比较 `/session/file.datatime` 与八目合并标定 `header.generated_at_utc`，确认标定生成时间距离采集参考时间不超过 48 小时。</p>

## 先看懂这条规则

- **检查什么：** 从 MCAP 的 session/file 元数据取得采集参考时间，再读取指定八目合并标定 JSON 的生成时间，统一换算到 UTC 后计算时间差。
- **什么情况下不通过：** 标定缺失、JSON 或时间字段无法解析、标定晚于采集，或标定早于采集超过 48 小时，都会失败。

### 判定标准

| 状态 | 怎么判 |
| --- | --- |
| **`pass`** | `0 <= age_seconds <= 172800` |
| **`warn`** | 不会出现；本规则不使用 warn 状态。 |
| **`error`** | age 小于 0、大于 48 小时，或任一输入文件、JSON、字段和时间格式无效。 |

**边界怎么算：**

- 年龄恰好为 0 小时或 48 小时时通过。

### 具体检查项

1. 从 MCAP 中读取 `/session/file` 消息，并提取一致的 `datatime` 作为采集参考时间；多个不一致值直接失败。
2. 读取精确 attachment `/comb_camera/comb_AYZ48630075.json`，解析 `header.generated_at_utc`。
3. 将两个时间转换为 UTC，计算年龄并按包含 0 和 48 小时的闭区间判定。

## 失败后建议

1. 检查 MCAP 是否包含精确名称为 `/comb_camera/comb_AYZ48630075.json` 的 attachment。
2. 检查 JSON 中 `header.generated_at_utc` 是否为合法 ISO 8601 时间，并确认其时区含义为 UTC。
3. 检查 `/session/file` 是否存在且 `datatime` 使用采集时间，而不是文件系统修改时间或当前时间。
